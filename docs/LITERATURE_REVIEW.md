## Thematic synthesis

**Platform feasibility and deployment.** Factory, WLDT, OpenTwins and edge–cloud platforms establish that physical/virtual messaging, protocol conversion and cloud-side services are practical. They address different architectural layers. A browser visualization, model integration or successful MQTT delivery is not alone a test of state freshness after delayed replay. Our architecture is deliberately a current-state synchronization subsystem; a deployable subscriber represents the cloud-side state service, while the executed test co-locates it locally.

**Freshness is established prior art.** Budgeted synchronization, AoI/AoDT metrics, synchronization formulations, and scheduling/energy optimization already study timely state. Consequently, an assertion that earlier DT work ignores freshness would be false. Neither coalescing nor round-robin nor sequence guards is individually presented as an invented algorithm. This project contributes an auditable combination and a matched evaluation under controlled recovery conditions.

**Resilience has multiple meanings.** Node failover maintains service availability; rate monitoring flags disturbances; a persistent outbox preserves a replay opportunity. These mechanisms answer different questions. A rate-monitor signal cannot establish whether received values are current. A complete local history cannot establish that a remote historical archive is complete. Receiver state and communication accounting must be reported separately.

**Experimental evidence must match the claimed layer.** ComBench motivates repeated, comparable conditions and resource observability. Our native loopback run exercises real MQTT QoS handshakes but controls dispatch at the application layer. A separate discrete-event model explores higher loads and longer outages. Neither substitutes for Linux packet impairment, wireless hardware or paid-cloud WAN measurements.

## Defensible research gap

The selected baseline provides a rate-oriented monitoring path, but its published code has neither a generation-time-aware current-state service nor a recoverable latest-state outbox policy. Within that baseline, it is therefore untested whether a rise in received traffic during benign backlog replay improves or harms current-state freshness. Across the reviewed works, we did not verify an exact experiment jointly separating **live-state age, finite-horizon delivery completeness, local durable audit completeness, monotonicity and queue/resource costs** for this baseline under the same MQTT workloads. This is a scoped evaluation gap, not an exhaustive claim that no such system exists anywhere.

## Refined research question and objectives

RQ: Under constrained edge dispatch and temporary disconnection, how does fair latest-state coalescing with monotonic cloud-side application compare with FIFO replay and expiry in state age, synchronization error, delivery completeness and resource cost?

1. Audit and execute the feasible MQTT core of the selected recent study, documenting paper/code/environment differences.
2. Implement a durable latest-state outbox, fair dispatch and sequence-checked receiver while retaining FIFO and epoch-only baselines.
3. Evaluate matched repeated synthetic workloads using actual MQTT and an explicitly separate application simulation; measure freshness, completeness, recovery and costs.
4. Test expiry and receiver-guard ablations, disclose regressions/unfavorable cases and establish the limits of deployment claims.

The predecessor RQ about QoS × buffering remains in the proposal history. The present evidence refines it toward application buffering/freshness because packet-level WAN impairments are not available on the executed host. Instructor confirmation of this refinement remains external.
